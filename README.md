# Espanso 단축어 분류

- `:` 목표·의도·맥락 파악, 계획·설계, 선택과 우선순위, 업무 정리.
- `;` 구현 코드·로그·실행 결과를 근거로 결함을 찾거나 수정·검증하는 엔지니어링 작업.
- 이름에 리뷰가 있어도 계획·설계·일반 결과물 검토는 `:`, 구현 검토는 `;`를 쓴다.
- 경계 항목: `:적대적리뷰`는 일반 결과물 판단, `;디테일`·`;문제발견`은 실제 기능과 동작의 결함 탐색, `:설계병목분석`은 설계상의 잠재 병목, `;실행병목분석`은 실제 측정 근거에 기반한 병목을 다룬다.
- 접두사는 분류이며 실행 권한을 뜻하지 않는다. 각 문구의 승인·수정 제한을 그대로 따른다.

## 줄바꿈과 공백 작성 원칙

- 여러 줄 문구는 `replace: |-`로 저장해 입력 시 줄바꿈이 유지되도록 한다. `>-`는 줄바꿈을 공백으로 합치므로 사용하지 않는다.
- 문장은 끝에서 줄을 나누고, 목적·검토 내용·제약·출력 형식처럼 주제가 바뀌면 빈 줄 하나로 구분한다.
- 제목과 목록 사이의 빈 줄, 하위 목록의 들여쓰기를 유지한다. 줄 끝 공백과 불필요한 연속 빈 줄은 제거한다.
- 서식만 수정할 때는 단축어 이름·순서·문구·명령·경로를 유지한다. 실제로 펼쳐지는 문구를 파싱해 공백 외의 내용이 바뀌지 않았는지 확인한다.
- Mac의 실제 입력 동작과 macOS 텍스트 대치 동기화는 별도로 확인한다.

## 단도리 3종: 준비 → 계획 정리 → 단속

- `:준비단도리` (준비·채비): 목표·조건·자료·권한·환경을 확인하고 착수 가능 여부를 판단한다.
- `:계획정리단도리` (계획·정리): 이미 수립된 계획을 바탕으로 실행 순서, 절차, 의존관계와 단계별 완료 기준을 정돈한다. 계획을 새로 만드는 단축어가 아니다.
- `:단속단도리` (단속·관리): 진행 중 발생할 수 있는 누락, 절차 이탈, 실패 위험을 예방하고 확인 시점과 후속 조치를 정리한다.

사용 순서: 착수 전에 `:준비단도리` → 계획을 수립한 뒤 `:계획정리단도리` → 작업 중과 완료 직전에 `:단속단도리`.
세 단축어는 분석·정리·제안까지만 수행하며, 코드나 설정의 실제 변경 및 실행 권한은 부여하지 않는다.

## 잡도리: 이미 확인된 잘못의 시정

- `:잡도리`: 근거로 확인된 오류·기준 위반·반복된 실수·미이행 시정 사항을 엄격하게 재검토하고, 시정 우선순위와 완료 증거를 제시한다.
- `:단속단도리`와의 차이: 단속단도리는 **문제 발생 전**의 누락·위험 예방을 맡고, 잡도리는 **문제 확인 후**의 바로잡기·재검증·재발 방지를 맡는다.
- 미확인 원인이나 담당자를 추정하지 않는다. 잡도리도 분석과 시정안 제시까지만 수행하며, 실제 변경은 별도 지시를 받아 진행한다.

## 치트키와 현실구멍

- `:치트키`: 정공법보다 적은 노력으로 같은 결과를 얻는 **합법적** 지름길(기존 도구·기능, 남이 푼 해법, 범위 재정의, 지원 요청 등)을 찾아 근거·대가·첫 행동과 함께 제안한다. 법·약관·정책 위반, 인증·검증 우회, 품질 기준 낮추기는 제외한다.
- `:현실구멍`: 계획·설계 문서·각종 문서·현재 세션의 결정이 성립하려면 참이어야 하는 숨은 전제를 꺼내, 사람·자원·환경·과정·측정 면에서 현실과 어긋나는 지점을 찾는다. `:적대적리뷰`가 결과물 전체의 결함을 보는 반면, 현실구멍은 "문서 밖 현실에서도 통하는가"에 집중한다.
- 두 단축어 모두 제안·점검까지만 수행하며 실제 변경·가입·구매·실행은 하지 않는다.

## 외부 전달 글 초안

- `:전달초안`: 세션 내용을 바탕으로 외부 사람에게 보낼 글 초안을 쓴다. 목적은 AI 말투 없이 핵심만 전달하는 단단한 문장이다.
- 첫 문장에 용건, 한 문장에 정보 하나, 요청 행동과 기한을 분명히 쓰고 번역투·빈 꾸밈말·기계적 나열·상투적 마무리를 금지한다.
- 설치된 한국어 윤문 스킬(예: humanize-korean)이 있으면 초안을 그 스킬로 다듬고, 사실·요청·기한이 바뀌지 않았는지 대조한다. 초안만 작성하며 발송·게시는 하지 않는다.

## 트리거 겹침 주의

- Espanso는 입력 끝이 트리거와 같아지는 순간 바로 펼친다. 그래서 `:설계`처럼 다른 트리거(`:설계리뷰`, `:설계병목분석`)의 앞부분인 트리거는 `word: true`로 두어 뒤에 공백·엔터를 쳤을 때만 펼친다.
- 새 트리거를 추가할 때는 기존 트리거의 앞부분이 되거나 기존 트리거를 앞부분으로 갖지 않는지 확인한다.

## 목표 확인과 점검

- `:목표성과`: 세션 최종 목표, 기여도, 기대 효과 등 성과 중심의 정리.
- `:목표체크`: 초보자도 이해하기 쉬운 평범한 언어로 목표, 진행 상태, 현재 겪는 걸림돌(이슈)을 진단.

## 세션 마무리

- `:세션마무리`: 세션 종료 전 PDCA 결과 보관 또는 일반 문서 정리, 병합된 작업 브랜치·워크트리 정리, 이번 세션의 백그라운드 작업 종료와 리소스 반납을 요청한다.
- 미완료 작업은 인계 기록으로 보존한다. 병합되지 않은 브랜치, 다른 세션이 사용하는 워크트리·프로세스, 소유권이 불명확한 리소스는 삭제하거나 종료하지 않는다.

## 계획 점검과 외부 리뷰

- `:플랜점검`: 현재 대화에서 Plan 문서의 요구사항 일치, 실현 가능성, 범위와 완료 기준을 사전 점검한다.
- `:외부리뷰`: 다른 AI 도구에 같은 계획을 전달해 독립적으로 검토하고, 받은 의견의 타당성을 평가한다. 사전 점검 결과가 있으면 함께 전달하되 결론을 그대로 믿지 않도록 한다.

두 단축어 모두 검토와 개선안 제시만 수행하며, 사용자 확인 전에는 계획 문서·코드를 수정하거나 다음 단계로 진행하지 않는다. 외부 도구를 실행할 수 없으면 실행 불가 사실과 전달용 리뷰 요청문을 제공한다.

## PDCA 완료 절차

- `;pdca:goal`(앞뒤 공백 없음): `/goal pdca finish`를 시작으로 Do → Analyze → Report → Archive → PR → PR 외부 리뷰 → 병합 → 배포 → 완료 보고 순서로 진행하도록 지시한다.
- 자동 결정은 확정된 목표·요구사항과 허용된 작업 범위 안에서 수행한다. 공식 권장사항과 검증된 관례를 참고해 목표 달성 가능성·안전성·단순성·유지보수성을 비교하며, 일상적인 선택은 반복 확인 없이 진행하되 필수 승인·권한·브랜치 보호 규칙은 우회하지 않는다.
- 핵심 기능의 로컬 실행 검증과 관련 테스트는 PR 생성·업데이트를 위한 푸시 전에 수행한다. 이후 동작에 영향을 주는 수정이 생기면 관련 검증을 반복하고, 병합 전 최종 변경본의 검증 결과를 확인한다.
- 외부 리뷰는 실제 독립 도구 또는 리뷰어의 검토가 있어야 완료로 인정한다. 리뷰 대상 커밋을 기록하고 기능·보안·데이터 처리·배포 동작에 영향을 주는 수정은 해당 부분을 다시 검토받는다. 동작에 영향이 없는 문서 오탈자 수정은 범위와 근거를 남기며 전체 리뷰를 반복하지 않는다.
- 배포 대상·정상 판정 기준·안전한 복구 절차를 확인하며, 병합 즉시 자동 배포되는 경우에는 병합 전에 이 조건을 충족해야 한다. 배포 실패 시 안전성이 확인된 절차로 복구·검증하고, 복구 방법이 불명확하면 임의 변경을 멈추고 현재 상태와 필요한 조치를 보고한다.
- Archive는 중간 기록 보관이다. 리뷰 후 변경 사항과 최종 검증·배포·복구 결과를 보관된 보고서에 연결하며, 배포 후 정상 동작까지 확인해야 전체 완료로 판정한다. 필수 검증·리뷰·승인·권한·배포 조건이 미충족이면 다음 단계로 넘어가지 않고 원인과 재개 조건을 보고한다.

## macOS 텍스트 대치 보조 항목

- `:list`: 전체 단축어 목록.
- `:설계`: `:설계리뷰`와 같은 문구를 사용하는 기존 무접두사 별칭의 새 이름.
- Espanso 단축어는 이 저장소를 정본으로 관리하며, macOS 텍스트 대치는 별도로 동기화한다. 이전 세미콜론 이름 6개는 새 콜론 이름으로 대체한다.

### `:설계병목분석` 추가하기

- [macos/bottleneck-check.plist](macos/bottleneck-check.plist)는 `:설계병목분석` 한 항목을 담은 macOS 텍스트 대치 가져오기 파일이며, Espanso와 동일한 분석 문구를 포함한다.
- GitHub에서 파일을 내려받은 뒤 **시스템 설정 → 키보드 → 텍스트 대치** 창에 드래그하고 **완료**를 누른다.
- 가져온 뒤 `:설계병목분석`을 입력해 설계·아키텍처의 잠재 병목 분석 문구와 줄바꿈을 확인한다. 실제 Mac에서의 가져오기와 입력 동작은 별도 확인이 필요하다.
